# SHOO 地址多级联动需求设计方案

> 版本：v1.0  
> 日期：2026-08-24  
> 范围：App 地址编辑/选择、Platform API 地址库、Admin 地址库管理（Mock 起步）  
> 目标国家（一期）：**中国（CN）**、**美国（US）**

---

## 1. 背景与目标

### 1.1 背景

当前 SHOO 地址表单为**自由文本**填写「城市」「省/州」，存在以下问题：

- 无法保证地址规范性与可校验性；
- 中美地址结构差异大（中国：省市区镇；美国：State / City / ZIP），单一 `region` 字段语义模糊；
- 结算、运费、税费等能力无法基于标准行政区划做规则；
- 后台仅有订单上的 `shippingAddress` 字符串，缺少结构化地址与地址库。

### 1.2 目标

1. 地址编辑页提供**成熟电商风格**的多级联动选择器（底部弹窗 + 多列滚动 / Tab 切换）；
2. 支持最多 **四级** 行政区划：**国家 → 省/州 → 城市 → 区/镇**（按国家配置实际层级）；
3. 一期默认支持 **中国、美国** 两套地区数据；
4. Platform API 提供**地址库（Region Library）**只读查询；Admin 可查看/维护 Mock 数据（二期可接真实数据源）；
5. 用户收货地址实体升级为**结构化字段 + 展示快照**，兼容现有列表/结算/订单展示；
6. 下单时将选中地址**快照**写入订单，不依赖后续地址变更。

### 1.3 非目标（一期不做）

- 全球所有国家完整数据；
- 地图选点、经纬度逆地理；
- 地址 OCR / 智能识别；
- 用户地址服务端 CRUD 全量同步（可放在 Phase 2，一期仍以本地存储为主 + 区域库走 API）。

## 2. 用户故事

| 角色 | 故事 | 验收 |
|------|------|------|
| 买家 | 新增地址时，点击「所在地区」弹出联动选择器，按国家逐级选择 | 四级选满前不可确认；选完后表单展示完整地区文案 |
| 买家 | 切换国家后，下级选项清空并重新加载该国数据 | CN ↔ US 切换行为正确 |
| 买家 | 编辑已有地址时，选择器回显已选层级 | 打开弹窗默认定位到已选节点 |
| 买家 | 中国地址选到「区/镇」；美国地址选到「City」即可（镇级可配置为可选） | 按国家规则校验必填层级 |
| 运营 | Admin 查看中/美地址库 Mock 数据 | 可浏览树形结构、版本号 |
| 开发 | Mock API / 真 API 均可驱动同一套 Flutter 选择器 | `USE_MOCK_API` 切换无代码改动 |

## 3. 交互设计（UX）

### 3.1 表单项布局（地址编辑页）

保留现有联系人字段，**替换**原「城市」「省/州」两个文本框为：

```
收货人 *
手机号 *
────────────────────────
所在地区 *          [ 请选择 > ]     ← 点击打开多级联动弹窗
  展示：中国 广东省 深圳市 南山区
────────────────────────
详细地址 *          [ 街道门牌号… ]
门牌号/楼层（选填）
邮编（选填，US 建议必填）
设为默认地址
```

**原则：**

- 「所在地区」为**只读汇总行**，不可手输，避免绕过校验；
- 「详细地址」仅填街道、楼栋、门牌（中国场景下**不含**省市区）；
- 邮编：中国选填；美国**建议必填**（表单校验可配置）。

### 3.2 多级联动弹窗（成熟电商模式）

参考淘宝 / 京东 / Amazon 地址选择：

```
┌─────────────────────────────────────┐
│  选择地区                      [×]  │
├─────────────────────────────────────┤
│  中国 > 广东省 > 深圳市 > 请选择    │  ← 面包屑 / 已选路径
├─────────────────────────────────────┤
│  [ 热门 ] [ 省份 ] [ 城市 ] [ 区县 ] │  ← Tab（或自动推进下一列）
├─────────────────────────────────────┤
│  北京市                             │
│  天津市                             │
│  河北省                             │
│  …                                  │  ← 当前层级列表，可搜索（二期）
├─────────────────────────────────────┤
│            [ 确定 ]                 │
└─────────────────────────────────────┘
```

**交互规则：**

1. 打开弹窗：若未选国家，默认列表为**支持国家**（CN / US）；
2. 选中某一级后：
   - 面包屑更新；
   - 自动加载并展示下一级列表；
   - 若该国配置的最大层级已选满 → 「确定」可点；
3. 点击面包屑任意层级 → 回退到该级重新选择（下级清空）；
4. 切换国家 → 清空已选下级，重新从省/州开始；
5. 点「确定」→ 回写表单 `regionSelection` 与展示文案；
6. 点遮罩 / 关闭 → 未点确定则**不修改**原选择（与成熟 App 一致）。

### 3.3 组件形态（Flutter）

| 组件 | 职责 |
|------|------|
| `SHOAddressRegionField` | 表单中的「所在地区」汇总行 |
| `SHOAddressRegionPickerSheet` | 底部弹窗容器（`showModalBottomSheet`） |
| `SHOAddressRegionPickerBody` | 面包屑 + 列表 + 确定 |
| `SHOAddressRegionPickerController` | 管理当前路径、加载子级、国家规则 |

状态管理建议：`Riverpod` + `AsyncNotifier`，按 `countryCode + parentCode` 缓存子级列表。

## 4. 各国层级映射（最多四级）

统一抽象为 **L1–L4**，按国家映射不同语义：

| 层级 | 中国（CN） | 美国（US） |
|------|------------|------------|
| L1 | 国家 | Country |
| L2 | 省 / 直辖市 / 自治区 | State |
| L3 | 地级市 / 直辖市区 | City |
| L4 | 区 / 县 / 镇（一期 Mock 到区为主） | 无（或 City 下可选 Community，一期**不要求**） |

**必填规则（一期）：**

| 国家 | 必填层级 |
|------|----------|
| CN | L1 + L2 + L3 + L4 |
| US | L1 + L2 + L3（L4 隐藏） |

> 说明：美国电商常见为 State + City + ZIP；四级中的「镇」对美国不强制。若未来扩展，可将 L4 用于 County / Township。

## 5. 数据模型

### 5.1 行政区划节点 `RegionNode`

```ts
// API / 共享 JSON Schema
{
  "code": "440305",           // 稳定唯一编码
  "name": "南山区",            // 本地化名称
  "nameEn": "Nanshan District", // 可选，Admin / 英文环境
  "level": 4,                 // 1=国家 2=省州 3=市 4=区县镇
  "countryCode": "CN",
  "parentCode": "440300",
  "hasChildren": false
}
```

### 5.2 用户地址 `SHOAddress`（升级版）

```dart
class SHOAddress {
  String id;
  String name;
  String phone;

  // 结构化地区（新）
  String countryCode;          // CN / US
  String? regionL2Code;        // 省/州 code
  String? regionL2Name;
  String? regionL3Code;        // 市 code
  String? regionL3Name;
  String? regionL4Code;        // 区/镇 code（US 可为空）
  String? regionL4Name;

  String line1;                // 详细地址（街道门牌）
  String line2;
  String postalCode;

  bool isDefault;

  // 兼容旧字段（迁移期读写）
  @Deprecated('Use regionL3Name') String city;
  @Deprecated('Use regionL2Name') String region;
}
```

**展示快照：**

```dart
String get regionSummary => switch (countryCode) {
  'CN' => '$countryName $regionL2Name $regionL3Name $regionL4Name',
  'US' => '$regionL2Name, $regionL3Name',
  _ => '...',
};

String get fullLine => [regionSummary, line1, line2, postalCode]
    .where((s) => s.trim().isNotEmpty)
    .join(', ');
```

### 5.3 订单地址快照

下单时写入订单（避免用户改地址后订单展示变化）：

```ts
shippingAddressSnapshot: {
  name, phone,
  countryCode,
  regionL2Name, regionL3Name, regionL4Name,
  line1, line2, postalCode,
  formatted: "中国 广东省 深圳市 南山区 科技园南路…"
}
```

一期可继续用 `Order.shippingAddress: string`，由快照 `formatted` 填充。

## 6. 地址库 API 设计（Platform API）

### 6.1 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/v1/regions/countries` | 支持的国家列表 |
| GET | `/v1/regions/children?country=CN&parentCode=440000` | 某父节点下子级；`parentCode` 为空时返回该国 L2（省/州） |
| GET | `/v1/regions/tree?country=CN&depth=2` | 可选：Admin 预览用，App **不建议**一次拉全树 |
| GET | `/v1/regions/meta` | 版本号、更新时间、各国层级配置 |

**响应包络：** 沿用现有 `{ code, message, data }`。

**示例：**

```http
GET /api/v1/regions/children?country=CN&parentCode=440300
```

```json
{
  "code": 0,
  "data": {
    "countryCode": "CN",
    "parentCode": "440300",
    "items": [
      { "code": "440305", "name": "南山区", "level": 4, "hasChildren": false },
      { "code": "440306", "name": "宝安区", "level": 4, "hasChildren": false }
    ]
  }
}
```

### 6.2 存储方案（一期 Mock）

**推荐：** `AppDocument` + JSON 文件（与现有 `addresses.json` 模式一致）

```
platform/apps/api/prisma/seed/data/regions/
  ├── meta.json              # 版本、国家配置
  ├── cn_l2.json             # 省级（或按 parent 分片）
  ├── cn_440000_children.json
  └── us_l2.json             # 50 states + DC
```

**分片策略：**

- 按 `parentCode` 分片存储子节点，App **按需加载**；
- 中国国家数据量较大，**禁止**单次返回全国四级全量；
- Meta 中声明 `dataVersion`，App 可本地缓存（`SharedPreferences` / 文件缓存） keyed by version。

### 6.3 国家配置 `RegionCountryConfig`

```json
{
  "countryCode": "CN",
  "name": "中国",
  "nameEn": "China",
  "maxLevel": 4,
  "requiredLevels": [1, 2, 3, 4],
  "labels": {
    "2": "省份",
    "3": "城市",
    "4": "区/县"
  }
}
```

```json
{
  "countryCode": "US",
  "name": "美国",
  "nameEn": "United States",
  "maxLevel": 3,
  "requiredLevels": [1, 2, 3],
  "labels": {
    "2": "State",
    "3": "City"
  }
}
```

### 9.2 缓存策略

| 层级 | 缓存位置 | TTL |
|------|----------|-----|
| 国家列表 + meta | 内存 + 本地 | 7 天或随 `dataVersion` 失效 |
| children 列表 | 内存 LRU | 当次会话 |
| 已选路径 | 地址实体 | 永久（随地址保存） |

### 9.3 Mock 对齐

`hos_mock_interceptor.dart` 增加：

- `GET /regions/countries`
- `GET /regions/children`
- `GET /regions/meta`

### 9.4 旧数据迁移

本地 `addresses_v1` 中已有地址：

```dart
// 迁移逻辑（一次性）
if (countryCode.isEmpty) {
  // 根据 region/city 文本尝试匹配；失败则标记需重新选择
  countryCode = 'US'; // 或根据 locale 默认 CN
  needsRegionReselect = true;
}
```

表单打开时若 `needsRegionReselect` → 地区行显示「请重新选择」。

## 13. 验收标准

### 功能

1. 新增地址：必须通过联动选择器选满必填层级，不可手输省市区；
2. CN 地址：可选四级且展示「中国 省 市 区」；
3. US 地址：选 State + City，无第四级；
4. 编辑地址：弹窗正确回显；
5. 切换国家：下级清空；
6. Mock / 真 API 行为一致；
7. 离线：已缓存的 children 可继续选择（可选，一期可仅提示网络错误）。

### 性能

- 单次 `children` 接口 < 100ms（本地 Mock）；
- 弹窗打开首屏 < 300ms；
- 中国数据不全量下载，包体增量可控（建议 < 500KB 压缩 JSON）。

### 兼容

- 旧地址可读；无法映射时提示用户重新选择地区；
- 旧 `city` / `region` 字段在迁移期双写，逐步废弃。

## 14. 风险与对策

| 风险 | 对策 |
|------|------|
| 中国全量四级数据过大 | 分片 + 懒加载；一期只做演示覆盖 |
| 美国无统一「镇」层级 | US `maxLevel=3`，不强制 L4 |
| 旧地址无法自动映射 | 标记 `needsRegionReselect`，引导用户重选 |
| 本地地址与服务端不同步 | 一期维持本地 CRUD；区域库只读走 API |
| 邮编校验复杂 | 一期仅 US 非空校验；格式校验二期 |
