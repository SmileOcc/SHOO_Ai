# SHOO 项目脚本说明

本文档描述仓库内 **CI / Git Hooks / 代码生成 / 迁移维护** 相关脚本与配置文件的用途、触发方式及常用命令。

---

## 一、脚本总览

| 路径 | 类型 | 用途 |
|------|------|------|
| `scripts/ci_check.sh` | Shell | 本机完整 CI 检查（与 GitHub Actions 一致） |
| `scripts/analyze.sh` | Shell | 轻量分析 + 测试 |
| `scripts/codegen.sh` | Shell | Freezed / JSON / l10n 代码生成 |
| `scripts/ci_protected_branches.sh` | Shell | 受 CI 保护的分支列表与判断函数 |
| `scripts/ensure_git_hooks.sh` | Shell | 自动安装 / 维护 Git Hooks |
| `scripts/setup_git_hooks.sh` | Shell | 手动启用 Hooks（兼容入口） |
| `scripts/bootstrap/post-merge` | Shell | clone 后 pull 时引导安装 Hooks |
| `scripts/bootstrap/post-checkout` | Shell | clone / checkout 时引导安装 Hooks |
| `scripts/migrate_framework.py` | Python | 一次性目录结构迁移（presentation 分层等） |
| `scripts/framework_migrate.py` | Python | 安全移动 core 文件 + 全局 import 重写 |
| `scripts/fix_imports.py` | Python | 框架迁移后按 feature 修复 import |
| `scripts/fix_feature_imports.py` | Python | 路径规则 + 文件名索引修复 import |
| `.githooks/*` | Git Hook | 受保护分支上的 CI 拦截与 pull 后维护 |
| `.gitconfig.hooks` | Git 配置 | 声明 `hooksPath = .githooks` |
| `.github/workflows/ci.yml` | GitHub Actions | 远程 CI 流水线 |
| `.vscode/tasks.json` | IDE 任务 | 打开项目时自动 ensure hooks |

## 二、CI 与质量检查

### `scripts/ci_check.sh`

**功能**：在本地执行与 GitHub Actions **完全一致** 的检查流程。

**执行步骤**：

1. `flutter pub get`
2. `dart format --output=none --set-exit-if-changed .`
3. `flutter analyze --fatal-warnings --no-fatal-infos`
4. `flutter test`

**使用场景**：

- 提交 / 合并 / push 到受保护分支前（由 Git Hook 自动调用）
- 手动预检：`bash scripts/ci_check.sh`

**依赖**：本机已安装 Flutter 且 `flutter` 在 `PATH` 中。

---

### `scripts/analyze.sh`

**功能**：轻量级本地检查，**不包含 format 校验**。

**执行步骤**：

1. `dart analyze lib test`
2. `flutter test`

**使用场景**：日常开发快速验证，比 `ci_check.sh` 更快。

**命令**：

```bash
bash scripts/analyze.sh
```

---

### `scripts/ci_protected_branches.sh`

**功能**：定义受 CI 保护的分支，并提供判断函数供 Git Hooks 使用。

**当前受保护分支**：`main`、`master`、`dev`

**导出函数**：

| 函数 | 说明 |
|------|------|
| `ci_is_protected_branch <分支名>` | 判断本地分支是否受保护 |
| `ci_protected_branch_from_remote_ref <ref>` | 从 `refs/heads/xxx` 解析受保护分支名 |

**维护说明**：新增保护分支时，需同步修改：

- 本文件中的 `CI_PROTECTED_BRANCHES`
- `.github/workflows/ci.yml` 的 `branches` 列表

## 三、Git Hooks

### 自动安装：`scripts/ensure_git_hooks.sh`

**功能**（幂等，可重复执行）：

1. 写入 `git config include.path ../.gitconfig.hooks`（加载 `.gitconfig.hooks`）
2. 为 `.githooks/*` 与 `scripts/ci_check.sh` 添加可执行权限
3. 将 `scripts/bootstrap/` 复制到 `.git/hooks/`，使 **pull / checkout** 也能触发安装

**自动触发时机**：

| 时机 | 触发方式 |
|------|----------|
| `git pull` | `.git/hooks/post-merge` → ensure |
| `git checkout` / clone 检出 | `.git/hooks/post-checkout` → ensure |
| 打开 Cursor / VSCode 项目 | `.vscode/tasks.json` → ensure |

**手动执行**：

```bash
bash scripts/ensure_git_hooks.sh          # 有输出
bash scripts/ensure_git_hooks.sh --quiet  # 静默
```

---

### 兼容入口：`scripts/setup_git_hooks.sh`

**功能**：等价于 `ensure_git_hooks.sh`，保留旧命令兼容。

```bash
bash scripts/setup_git_hooks.sh
```

---

### 引导脚本：`scripts/bootstrap/`

| 文件 | 安装位置 | 功能 |
|------|----------|------|
| `post-merge` | `.git/hooks/post-merge` | pull 完成后调用 `ensure_git_hooks.sh` |
| `post-checkout` | `.git/hooks/post-checkout` | checkout 完成后调用 `ensure_git_hooks.sh` |

> `.git/hooks` 无法提交到 Git，由 `ensure_git_hooks.sh` 在本地自动生成。

---

### 项目 Hooks：`.githooks/`

| Hook | 触发时机 | 行为 |
|------|----------|------|
| `pre-commit` | 在受保护分支上 `git commit` | 运行 `ci_check.sh`，失败则阻止提交 |
| `pre-merge-commit` | 在受保护分支上 `git merge` | 运行 `ci_check.sh`，失败则阻止合并提交 |
| `pre-push` | push 到 `origin/main|master|dev` | 运行 `ci_check.sh`，失败则阻止 push |
| `post-merge` | pull 完成后 | 静默运行 `ensure_git_hooks.sh` |
| `post-checkout` | 切换分支 / 检出后 | 静默运行 `ensure_git_hooks.sh` |

**跳过检查**（不推荐常用）：

```bash
git commit --no-verify
git merge --no-verify
git push --no-verify
```

---

### 配置文件：`.gitconfig.hooks`

**功能**：仓库内 Git 配置片段，声明：

```ini
[core]
    hooksPath = .githooks
```

通过 `ensure_git_hooks.sh` 写入本地 `include.path` 后生效。

## 四、远程 CI

### `.github/workflows/ci.yml`

**功能**：GitHub Actions 流水线，与 `scripts/ci_check.sh` 检查项一致。

**触发分支**：

- `push` → `main` / `master` / `dev`
- `pull_request` → 目标为 `main` / `master` / `dev`

**步骤**：`flutter pub get` → format → analyze → test

**查看结果**：GitHub 仓库 → **Actions** 标签。

---

## 五、代码生成

### `scripts/codegen.sh`

**功能**：一次性执行项目代码生成。

**执行步骤**：

1. `flutter pub get`
2. `dart run build_runner build --delete-conflicting-outputs`（Freezed / json_serializable 等）
3. `flutter gen-l10n`（国际化 ARB → Dart）

**使用场景**：修改 `@freezed` 模型、JSON 注解或 `l10n` 资源后。

```bash
bash scripts/codegen.sh
```

## 六、迁移与维护（Python）

> 以下脚本为 **历史迁移 / 批量修复** 工具，日常开发一般不需要运行。执行前建议先提交或备份工作区。

### `scripts/migrate_framework.py`

**功能**：一次性 **presentation 目录分层迁移**（pages / state / widgets 等），按文件名后缀自动归类并移动文件。

**适用**：早期 SHOO 目录结构重构。

---

### `scripts/framework_migrate.py`

**功能**：**安全移动 core 层文件**（storage / cache / network 等路径调整），并对全仓库 `package:shoo/...` import 做全局替换。

**适用**：core 模块路径变更后的批量迁移。

---

### `scripts/fix_imports.py`

**功能**：框架迁移后，按 **feature 维度** 修复 broken import（相对路径 → package import、旧类名替换等）。

**适用**：`migrate_framework.py` / `framework_migrate.py` 执行后的 import 补全。

---

### `scripts/fix_feature_imports.py`

**功能**：结合 **路径重写规则** 与 **文件名索引**，批量修复 feature 层错误 import。

**适用**：大规模 import 路径不一致时的自动化修复。

**运行示例**：

```bash
python3 scripts/fix_feature_imports.py
```

## 七、IDE 集成

### `.vscode/tasks.json`

**功能**：定义 VS Code / Cursor 任务 **「SHOO: Ensure Git Hooks」**。

- `runOn: folderOpen`：打开项目文件夹时自动执行 `ensure_git_hooks.sh --quiet`
- 无需手动运行 `setup_git_hooks.sh`

## 九、新增受保护分支

若需将例如 `dev_odd` 纳入 CI：

1. 编辑 `scripts/ci_protected_branches.sh`：

   ```bash
   CI_PROTECTED_BRANCHES=(main master dev dev_odd)
   ```

2. 编辑 `.github/workflows/ci.yml`：

   ```yaml
   branches: [main, master, dev, dev_odd]
   ```

3. 本地执行一次 `bash scripts/ensure_git_hooks.sh` 确保 hooks 更新。
